# Безопасность

## Как сообщить об уязвимости

Если вы нашли уязвимость в Shop API, не создавайте публичный Issue. Напишите на **aibolkazbayev@gmail.com** с темой «Shop API security»: что нашли, как воспроизвести, чем это грозит. Отвечу в течение трёх дней.

## Что сделано

- Пароли — scrypt с солью (`app/security.py`); слабые и популярные пароли не принимаются.
- 5 неудачных входов за 15 минут на пару «email + IP» → 429 с `Retry-After`; второй рубеж — 20 попыток на один email с любых адресов.
- Регистрация ограничена 10 в час с одного IP.
- Заголовки безопасности на каждом ответе: CSP, HSTS, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy.
- CORS — только адреса своего фронтенда, без «*».
- Роли: управлять каталогом и смотреть сводку может только администратор; чужие заказы выглядят как несуществующие.
- Тело запроса больше 256 КБ отклоняется до разбора; ошибки 500 не раскрывают подробностей, только ID запроса.
- ID запроса в каждом ответе и строке журнала — по нему находится ошибка пользователя.
- Каждый CI: pip-audit (уязвимые зависимости), CodeQL (анализ кода), OWASP ZAP (скан работающего API).
- Тесты: `tests/api/test_hardening.py`.
